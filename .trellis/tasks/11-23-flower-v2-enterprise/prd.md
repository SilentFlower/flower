# Flower v2 企业服务接入

## 目标

用真实企业入口验证共享运行时能够承接现有业务。先验证一个入口，再按验证结果安排迁移顺序。

## 当前依据

本任务以[目录与占位工具整理](../11-23-flower-v2-layout/prd.md)后的应用入口为基线，验证业务接入共享核心。

- GitLab 评审由 CI 参数和服务身份驱动，入口为 `apps/code-reviewer/src/run.ts`。现有回归包括评论格式、阻塞等级、退出码、网关失败处理和遥测。
- 钉钉入口按会话读取 Redis 历史，入口为 `apps/ops-bot/src/agent-factory.ts`。保留消息接收、模型回复与历史恢复。

## 验收草案

- [ ] 依赖共享核心的运行、工具及事件契约。建议首个入口选 GitLab 评审，使用可重复的 MR 样例进行只读试跑。
- [ ] 对照现有评审用例核对工具权限、评论载荷、退出码和 Observer 事件。在测试环境记录预期写入，避免对同一 MR 重复发评审。
- [ ] 钉钉入口纳入迁移时，覆盖历史恢复、用户隔离和流式回复。
