# 共享 pi 长会话续接

共享运行时在 pi Agent 的模型流入口计算预算。估算使用锁定的 pi-ai 1.6.0 `estimateMessageTokens`，计入当前系统提示与工具声明，额外为中日韩文本、输出和下一轮工具结果预留空间。原请求、附件引用、模型消息和工具回执继续归档。实际请求只使用已保存的摘要和保留的完整消息，优先在用户轮次边界切分，超大的同轮工具结果可在成组的调用与结果之间切分。当前任务和已授权附件保留在模型请求里。工具归档及摘要均是会话数据。

原生 pi 宿主通过同一个 `SessionGrant.streamFn` 接收摘要请求，`purpose: "summary"` 标识用途并提供输出预算。没有独立摘要凭据。coding-agent 的高级切分接口使用其自己的会话条目，Flower 两端原生 pi 宿主共用这里的检查点。`createExecution` 自定义适配端可沿用其 SDK 的窗口策略。企业 GitLab reviewer 的既有单次 CLI 走原适配入口。

一个成功请求原子提交完整历史和可选 `contextCheckpoint`。摘要按每批剩余 token 预算装入记录，留足输出和估算余量。批次没有固定次数上限。摘要失败或取消时保留上一个检查点及完整归档。网关明确报窗口溢出且尚未输出内容时，当前模型调用最多尝试一次更紧的压缩重试。过大的当前材料保留原请求并提示缩减或校准窗口。

原生成功请求保存用户消息索引，归档消息同时保存请求 ID。未完成任务的工具回执使用独立归档角色，模型投影时转为待核对数据。早期 `version: 1` 快照仍可按成功轮次恢复图片。早期候选中的无标记回执只在成功轮次的结构和身份均能对齐时兼容回读。同名附件和重复输入仍绑定原来的请求和附件位置。恢复过程中已完成的工具不会重放。

Desktop 的模型编辑可声明有效窗口，整数范围 1024 至 10000000，清空回到锁定的 pi 静态目录或未知模型的 32768 兜底。目录同名未限定 ID 用较保守的已知窗口。工作台在切换模型、会话、恢复工作进程和请求结束时刷新占用估算，显示窗口来源。估算基于归档的当前可见上下文，待提交的草稿不计入。

Linux 源内回归使用真实 Desktop worker 的独立 Node 进程、现有模型网关和合成回环服务。上传两页 PDF 与 `预算表!B7`，生成差额 37 的核对报告，积累记录直到触发 4096 窗口的摘要，然后重启子进程并检查续接请求、来源、历史和附件引用。复核用例另以 8192 窗口加载重复 16000 次的旧输入，回环观察到 15 次摘要和 1 次续接，最近一轮和完整原文保留，无新增工具调用。图片回归覆盖失败回执、同输入和同名附件，以及错误索引与错误归属的拒绝。共享核心回归另覆盖队列、身份隔离、无重放、多工具、摘要失败、取消与溢出。隔离 Windows 验收可沿用两页 PDF/工作簿用例，从候选 EXE 的正常入口核对实际请求、估算显示、重开原附件及报告。
