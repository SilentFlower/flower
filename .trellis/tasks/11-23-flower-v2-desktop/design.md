# Flower Desktop 工作台设计

## 产品和进程边界

开源分支 `v2` 的 Electron 主文档直接展示本地工作台。应用将会话与目录许可保存在当前系统用户的产品资料目录。企业版的账号档案使用独立路径。Main 接受受限的 preload 操作，校验发送窗口、主文档、文件归属与工作区权限。模型凭据由 Host 管理，子进程加载共享核心执行任务。

用户按自己的服务配置基础地址和模型名。远程模型地址使用 HTTPS。回环上的本机模型可按其要求使用 HTTP 和免密协议。配置期间保留当前任务草稿。凭据通过系统提供的保护机制持久化。

## 外观组件和主题

首页以 Cindy 0.1.143 的中文 Windows 界面作为布局与交互参照。保留 Flower 独立的品牌标识和 Windows 原生窗口控制。flower2api 的 `apps/web/src/theme` 和 `components/ui` 提供主题种子、语义色、基础控件和设置页的组织参照。Flower Desktop 使用原生 DOM 和 CSS 实现同一模式。

主题种子保存模式、强调色和两项首页文案。首帧加载本机外观，按系统或用户模式派生语义色和可读按钮文字。设置面板使用工作台实际按钮、表单和弹窗样式提供实时预览。保存仅写当前桌面外观，取消恢复原值。操作系统窗口控件由 Host 接受浅色、深色两个固定值。

### 工作台输入区与模型选择

Cindy 截图视口为 1282 × 801 像素。工作面底色约为 `#f2f2ed`，左侧导航宽约 260 像素。首页品牌和编辑卡距主区左缘约 44 像素，卡片约 932 × 140 像素，使用 `#fdfdf8` 浅色表面。标题栏高约 45 像素。跟随系统与用户自定义的深色模式继续使用可读的语义色。

Flower 首页用原创 Q 版助手头像、浓黑字标和短色标建立自己的身份。角色采用自然黑短发、灰色高光与红花发夹，主页、侧栏、消息和设置共用同一张圆形头像。头像和字标一同左对齐，下面是任务编辑卡和纵排任务建议。建议涉及浏览工作区、提炼待办、汇总数据、生成分析报告。用户点击建议后在同一输入框继续编辑，由用户显式发送。已有草稿保留。首页和空会话使用品牌起始页。进入有消息的会话后，主要空间用于阅读消息和交付物，继续使用紧凑的双层输入卡。

侧栏承载新建、目录、会话搜索、助手和会话历史。本机设置使用底部入口。搜索匹配会话名称及工作区，已有会话可按需切回。侧栏后退和前进只访问已经打开过的首页或会话。底部的本机工作台按钮显示产品版本并打开设置，用户可在此配置模型服务或进入外观设置。侧栏折叠偏好保存在本机。

- 上层编辑任务，下层左侧放目录或附件按钮及当前权限，下层右侧依次放当前模型及发送箭头。首页和已有会话使用同一组件。窄窗时优先为编辑及发送保留空间，过长的模型名可省略展示。
- 模型名打开就地选择器。参照 Qone 的两张截图，紧凑面板显示当前模型、图标及可用的推理强度。头像滑块随选择移动，用户可从同一入口换模型或打开设置。主题沿用 Flower 的字体、色彩、头像和焦点样式，尊重系统减弱动效偏好。
- 设置将模型和外观放在同一导航下。模型页按服务商列出模型，支持模型发现、手工添加和切换。厂商或模型标识使用随应用分发的图形，未识别的模型显示通用图标。
- 推理能力与图标分别决定。Host 按当前服务和模型保存支持的强度与所选档位，在下一次模型请求中使用该配置。使用服务默认值时沿用原请求。旧配置进入本地服务列表，密钥留在系统凭据保护边界之内。
- 将模型能力和请求协议分开处理。兼容网关的推荐档位可来自服务目录或 pi 随包提供的模型条目。出站请求仍使用用户已经配置的服务和协议。手动调整及关闭优先于内置推荐，未知型号沿用服务默认值。编辑页按当前策略呈现推荐来源或手动选项。
- 编辑页的标题区显示厂商图标和模型 ID，推理区域就地切换推荐、手动、服务默认三种策略。推荐从 pi 自带目录读取模型，并由 `getSupportedThinkingLevels` 取档位，服务明确公布档位时采用该声明，关闭思考需有相应的协议字段。手动策略直接展示可选档位，同一档位清单只出现一次。
- 模型卡共用一层悬停背景，切换模型和编辑模型分别提供键盘焦点。输入框的推理滑轨沿用 Flower 头像和主题强调色，浅粉和玫瑰色花瓣在已填充轨道内起伏、翻转。减弱动态效果时保留静态档位和键盘操作。
- 模型选择沿用原有运行中和排队状态约束。切换保留草稿和附件，已保存的模型设置在重启后恢复。缺少服务配置或模型发现不可用时，给出与当前状态对应的配置入口。
- 主题设置在宽窗分开编辑和实时预览，窄窗按阅读顺序排列。保留键盘操作、取消和保存。

### 当前会话的工作区权限

输入卡的权限按钮是本会话磁盘工具的策略入口。模型连接和会话历史有各自的本地配置。读取工作区目录、文本及查看或汇总 Excel 属于读操作。生成报告和汇总工作簿属于写操作。

| 模式 | 工具可执行的操作 |
| --- | --- |
| 只读 | 浏览、读取和计算，在对话里给出结果。 |
| 写入前询问 | 读取直接执行。每次新建交付物前展示工作区、输入文件及预定输出，由用户决定本次写入。 |
| 自动审批 | 在所选工作区内使用现有工具，直接生成交付物。 |

原生目录选择决定文件范围，系统选择器从当前或最近工作区开始，WSL 目录通过共享路径选择。工具在写入路径生效前执行对应策略，授权决定只对应本次会话中的这次写入。切换到其他会话时，原会话继续等待并在侧栏标为待批准。拒绝、取消任务或退出应用结束该次授权等待。会话权限随会话保存，旧格式会话继续沿用自动审批。

## 工作台与文件

用户选择本机目录后运行共享核心。文本与 Excel 工具校验实际路径，仅在获准目录内读取输入、创建交付物。用户显式提交后执行。打开已有会话时恢复历史和交付记录。

主进程将会话所属的工作区标识、目录名和路径提供给侧栏。工作区视图复用原有会话，按工作区标识分组，以路径区分同名目录。首次使用沿用平铺视图，本机记住用户选定的显示模式。视图切换和组的展开、收起仅影响侧栏，会话选择、编辑器草稿、任务执行与工具权限继续由原有流程管理。

右侧面板通过 Host 读取当前会话授权目录。目录按需分页，Markdown 报告沿用聊天中的本地排版组件，工作簿预览显示有限的工作表样本。图片通过临时 Blob URL 显示，PDF 按需加载随包分发的 PDF.js 并逐页绘制，关闭或切换预览时释放资源。DOCX 从正文 XML 提取段落，CSV/TSV 以行列呈现，源码使用纯文本。聊天区右上角的开关紧邻面板边缘，面板工具行提供放大、还原与关闭。切换会话时清除先前预览，丢弃过期读取结果。消息内的「预览」和文件列表使用同一条读取路径。

### 右栏停靠与窗口扩展

参照 Cindy 0.1.143 的 `SidebarWindowExpansion` 和面板拖放。渲染层以 `data-panel-side` 决定面板位于聊天区左侧或右侧，网格换位不重建面板节点，文件、预览和 Git 内容保持不变。停靠位置和栏宽一样保存在本机偏好。

- Preload 增加 `setPanelExpansion(width)`，Main 只接受来自可信主文档的有限数值，把 CSS 像素按页面缩放换成窗口坐标。宽度大于零时记录扩展前后的外框，在 `screen.getDisplayMatching` 的工作区内先占用右侧空余，再向左平移补足缺口，宽度不超过工作区。宽度为零时按「当前外框减去扩出宽度、横坐标加回平移量」还原，原本在工作区内的窗口还原后仍限制在当前显示器内。最大化或全屏期间不扩展；此时收起会登记待还原，退出最大化后再执行。页面重载时清理残留扩展。
- 渲染层在非窄窗并排打开面板时请求扩展，左右停靠共用同一份扩展，换位只交换网格列，不改变窗口。过渡期间把聊天列冻结为当前像素宽度，等待页面宽度达到 Main 返回的值后解冻，避免聊天区闪动。扩展期间 `--layout-vw` 等于「窗口宽度减去扩出宽度」的百分之一，侧栏宽度、标题栏留白、输入区模型按钮和首页字标等原先使用 `vw` 的尺寸改用这个变量，保持聊天区几何。
- 标题栏空白处按下后移动超过 6 像素才进入拖动，按钮、标签、输入框和调宽手柄排除在外。拖动中显示跟随指针的面板卡片，按指针位于内容区左半或右半高亮目标槽位。松手提交，Esc 或指针取消时还原，结束拖动后吞掉一次点击。标题栏的停靠按钮提供键盘等效操作，并通过状态区域播报结果。调宽手柄和键盘调宽按停靠方向计算。

每次提交保存有序的附件引用，队首重新核验授权后由宿主读取实际证据；企业宿主可提供自己的引用与读取方式。工作区文件原地读取。明确选中或拖入的外部文件及粘贴截图保存为会话私有副本，模型工具通过单文件引用读取，产物留在当前工作区。输入框、消息和右栏共用图片查看器，历史图片优先显示当时提交的内容。

助手回复在渲染层将 Markdown 转为语义化段落、列表、强调、代码、引用和表格。存储层继续保留模型返回的文本，使既有会话在新版中直接获得排版。消息中的普通文本、文件产物和工具步骤各自沿用对应组件。宽代码块和表格在消息内滚动。

## 桌面 UI 组件及演进顺序

模型设置、主题设置和工作台共用颜色、字型、间距、焦点样式、按钮和反馈。会话列表、任务输入框、消息、执行步骤、交付文件负责各自的交互。渲染入口将当前会话数据和操作回调交给组件，Electron Host 负责模型配置、目录和文件权限。今后新增一种工具时，优先让它的事件和产物进入现有消息。当前组件和调用点见[桌面组件目录](../../../apps/desktop/workbench/ui/README.md)。

报告和工作簿预览由右侧工作区面板承载。面板关闭后，焦点返回打开预览的交付文件按钮。桌面内部的多个页面直接共用 `workbench/ui`；出现第二个实际客户端需要同一组件时，再评估跨应用抽取。

Host 保存独立的工作区列表，启动时从旧会话恢复目录；先持久化删除意图，再清理本机记录和会话附件目录。Git 通过当前工作区归属校验，Windows 使用本机 Git，WSL 使用目录所属发行版的 Git。文件页通过会话与草稿或消息归属打开附件。
