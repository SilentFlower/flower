# Brief — 第二档 追问、队列与会话检索

## Goal

- 让用户能就回复片段追问或另开侧边追问、在运行中调整和插入待发消息、按正文找回旧会话、主动压缩上下文，并补齐中断恢复、交付元信息、Toast 撤销与全局指令。

## Scope

- 选中回复文字后的「引用」与「侧边追问」：浮动工具条和回复区右键菜单；侧边追问放在右栏，只读、只收文字，每个主会话一个
- 输入框上方的排队队列：行内编辑、删除、拖动排序、停止后暂停、重启后保留；运行中「插话」注入当前回复
- 上下文详情卡的「压缩上下文」，时间线中的压缩分隔
- 侧栏搜索匹配会话正文，显示命中片段，点击跳到命中的轮次
- 输入 @ 补全工作区文件；从文件面板拖文件到输入框
- 启动时的中断横幅，提供「全部继续」「忽略」；会话内按钮改为「继续任务」
- 交付卡片显示 `汇总.xlsx` 的工作表数与行数、Markdown 报告的字数
- Toast 组件；删除会话曾改为「立即删除 + 8 秒撤销」，试用后恢复确认框（R11）
- 试用反馈修订 R10–R15：压缩分隔区分自动/手动并修复旧轮次不显示、搜索入口改名与片段标签、文件浏览器开关移入标题栏、侧边追问标签页内首条即新建、输入框上方渐隐与「新消息」胶囊
- 设置中的个人「全局指令」；读取工作区根下的 `FLOWER.md`
- 共享运行时 `packages/agent-runtime` 新增插话与手动压缩接口

## Non-Goals

- 侧边追问不支持附件、排队、写入，也不能同时开多个
- 只显示最近一次压缩的分隔；压缩摘要不能查看或编辑
- 搜索不覆盖工具结果、附件正文和侧边追问；正文索引只在内存中，不写盘
- 不做企业统一下发全局指令（归 `v2-company`）；`AGENTS.md` 不会被当作约定文件读取
- 不做 PDF、DOCX 交付物的元信息（目前也没有这类产物）
- 启动时不自动续跑中断的任务，要用户点「全部继续」
- 第三档范围不在本任务内

## Technical Overview

- **插话**：Main 在送达前一直保留该队列项。共享运行时调用 pi 的 `agent.steer`，在当前一步结束后注入。送达时运行时在 `RequestRecord.steers` 记下原文和插入位置（`textOffset`），并发出新事件 `steered`；如果运行在送达前结束，Main 把该项放回队首。
- **队列**：队列从运行时移到 Main 的会话记录，存在 `workbench.json` 里。会话有活动请求时，提交一律进队列；收到终态事件后自动派发队首；用户取消或应用重启后队列暂停。
- **侧边追问**：Main 复制父会话已完成的 `messages` 和检查点，写成一个隐藏会话文件，注册给 worker 时带上 `readOnly`。worker 据此去掉写入类工具。
- **手动压缩**：运行时的 `compact` 复用现有摘要逻辑，压缩期间占用会话的活动位，阻止调度新请求。分隔线位置由检查点的 `through` 和请求的 `userMessageIndex` 推导，不新增需要落盘的字段。
- **搜索与中断识别**：Main 维护一份内存正文索引（按文件修改时间复用），搜索和启动扫描共用；结果跳转用的是新增的 `thread().reveal(requestId, query)`。
- **全局指令**：worker 授权时依次拼接「系统提示 + 个人指令 + `FLOWER.md`」，每轮重新读取，下一轮即生效。

## Context & Decisions

- 现状：运行中再发的消息排在运行时里，只能取消，停止后会自动继续跑；只有自动压缩；侧栏搜索只匹配名称和工作区；中断要到首次打开会话时才被修正；系统提示写死在 worker 里。行号证据见 `research/tier2-code-facts.md`。
- **【关键决定】剩余九项合并在一个任务里，分三批实现：输入区 → 检索与上下文 → 零散体验。每批单独提交，出问题只需回退那一批。**
- **【关键决定】插话真正注入正在进行的回复（pi `steer`），不采用「停止当前再发送」。这要改共享运行时并新增 `steered` 事件；code-reviewer 不提供 `steer`，调用插话会被拒绝，它现有的流程不受影响。**
- **【关键决定】队列从共享运行时移到 Desktop Main。用户能编辑、排序队列，重启后队列还在；停止运行后不再自动接着跑，要用户点「继续」或再发一条。**
- **【关键决定】侧边追问本档就做：放在右栏，只读、只收文字，每个主会话一个，重启后保留，用户关闭或删除主会话时一起删除。打开时只能参考主会话已完成的轮次，看不到当前正在运行的那一轮。**
- **【关键决定】删除会话保留确认框（试用后撤回 8 秒撤销），确认后立即删除；运行或排队中的会话需先结束任务。**
- **【关键决定】全局指令分两层：个人设置（最多 4000 字，本机所有会话生效）加工作区根下的 `FLOWER.md`（最多读 8000 字）。同部门共用一个工作区目录就能统一口径；`AGENTS.md` 不读，避免代码仓库里写给开发工具的说明混进业务问答。**
- **【重要限制】会话内的「继续任务」就是原来的「重试」：用原输入和附件重新发起一轮。中断前已输出的那段回复不会进入上下文，只有工具回执会。**

## Risks

- **【交付风险】pi 的 `steer` 送达时机取决于当前一步什么时候结束。工具执行很长时，插话会等较久才送达；如果运行在送达前失败，插话会回到队首，需要实测确认这条路径不丢消息、不重复发送。**
- **【交付风险】在回复选区上右键，需要用渲染层的 `preventDefault` 拦截原生菜单。如果 Electron 拦不住，会弹出两份菜单，就得改用 Main 端去重，第一批要先验证。**
- 正文索引首次搜索时要读全部会话文件。会话很多、文件很大（单个已有 635 KB）时，第一次搜索可能明显变慢；之后按文件修改时间复用，不再重读。

## Acceptance

- 选中回复文字可以引用到输入框，也可以打开侧边追问。侧边追问能得到回答，主会话继续运行；侧边追问写不出文件，重启后仍在。
- 运行中发送的消息进入队列，可以编辑、排序、删除，按顺序发送；停止运行后队列暂停，重启后保留。插话的内容会体现在当前回复里，并以气泡显示在对应位置。
- 手动压缩后圆环下降、时间线出现分隔，下一轮仍能引用压缩前的事实；压缩失败时上下文不变。
- 按正文能搜到会话，显示高亮片段，点击跳到命中的那一轮。
- 输入 @ 能补全并加入工作区文件；从文件面板拖文件也能加入。
- 强制退出后重启出现中断横幅，「全部继续」后这些会话重新运行。
- `汇总.xlsx` 卡片显示工作表数与行数，报告卡片显示字数。
- Toast 最多 3 条、相同内容去重、悬停时暂停；删除会话先确认、确认后立即删除。
- 回环网关收到的请求体里，系统提示依次包含个人指令和 `FLOWER.md` 内容。
- Desktop、agent-runtime、code-reviewer 的测试，以及构建、类型检查、Biome 全部通过；窄窗、深浅色、减弱动效、中文输入法、切换会话下都可用；Windows 打包后实机回归（不能打包时说明原因，并用浏览器夹具补足）。
