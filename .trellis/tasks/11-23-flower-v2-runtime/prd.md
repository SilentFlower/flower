# Flower v2 共享 pi 运行时

## 目标

完成目录与内容整理后，让企业 Node 入口和最小桌面子进程加载同一份共享核心构建产物，各自完成一次可复现的只读任务。 [前置布局任务](../11-23-flower-v2-layout/prd.md) · [父设计第 5.2 节](../11-23-flower-v2/design.md#52-共享核心双宿主验证)

## 需求及边界

- 宿主提供主体身份、模型访问能力、授权工具、工作区及会话存储。企业端使用受控服务身份，桌面端使用受控员工身份。真实员工登录由 Desktop 子任务负责。
- 两端按相同契约接收文本增量、工具调用及结果、运行终态。事件可归属到具体会话和运行。
- 在[升级到 pi 1.6.0](../11-23-flower-v2-pi-upgrade/prd.md)完成后验证真实会话与工具循环。受控模型响应和本地只读样例用于复现。
- 以前置任务交付的 `apps/code-reviewer`、`apps/ops-bot` 和 `apps/observer` 为基线，使用 `apps/code-reviewer` 的现有只读评审契约。本阶段包含本地 Node 子进程和进程间通信验证。真实企业业务切换、company 分支 CI、Windows 安装版、登录与发布在后续集成验收。

## 验收标准

- [ ] 记录两个宿主加载的核心构建标识及 pi 版本。同一份只读输入在两端产生预期的工具结果和运行终态。
- [ ] 两个主体并行时，各自只能读取获准工作区和会话，工具及事件归属正确。
- [ ] 同一会话依次提交 A、B、C，分别取消运行中的 A、排队中的 B 和排队中的 C。剩余请求按原顺序执行。取消进行中的文件读取后，宿主仍可接受后续请求。
- [ ] 重启子进程后恢复原主体已提交的历史和结果，中断任务状态可见。仅读取历史时，工具执行及外部写入次数均为零。
