# 通用代码评审清单

## 正确性

- 边界条件是否处理(空数组、null、超长输入、零、负数)
- 错误处理是否完备(catch 是否吞掉错误、是否打印有用信息)
- 并发场景是否安全(竞态、死锁、共享状态)
- 资源是否释放(文件句柄、数据库连接、定时器、事件监听器)

## 可读性

- 命名是否准确表达意图(避免缩写、避免歧义、避免否定形式如 `notEmpty`)
- 函数是否单一职责;过长函数(> 50 行)需要给出拆分建议
- 复杂条件表达式应抽出布尔常量(`const isAdmin = user.role === "admin"`)
- 魔法数字 / 字符串应抽出常量

## 安全

- 是否有 SQL 拼接(应该用参数化)
- 是否有 XSS 风险(用户输入直接拼到 HTML)
- 是否硬编码密钥 / token / 测试账号
- 路径拼接是否做了规范化(防穿越)

## 性能

- 循环里有没有 O(N²) 的隐藏开销(嵌套查找、循环里 await)
- 数据库查询有没有 N+1
- 是否有不必要的同步 I/O 阻塞

## 测试

- 新增逻辑是否有对应单测
- 修改的代码是否破坏现有测试假设
- 边界情况是否有测试

## 与团队规范的契合

- 日志格式是否符合项目规范
- 错误码是否在项目错误码表里
- 监控埋点是否到位(关键流程)
